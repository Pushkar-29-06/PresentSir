# API guide

The current API uses root paths. It does not currently prepend `/api/v1`.

## Authentication

```http
POST /auth/login
Content-Type: application/json

{"login_id":"faculty001","password":"Faculty@123"}
```

Use the returned access token:

```http
Authorization: Bearer <access_token>
```

Useful routes:

- `POST /auth/login`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /me`
- `GET /health`

## Faculty offering and slot

```http
GET /faculty/offerings
POST /faculty/slots
```

Example slot:

```json
{
  "offering_id": 1,
  "day_of_week": 1,
  "start_time": "10:30:00",
  "end_time": "11:30:00",
  "room": "B-204"
}
```

## Attendance session

```http
POST /attendance/sessions
POST /attendance/sessions/{session_id}/start
GET /attendance/sessions/{session_id}/qr
POST /attendance/sessions/{session_id}/CLOSED
POST /attendance/sessions/{session_id}/SAVED
POST /attendance/sessions/{session_id}/SUBMITTED
```

Example session creation:

```json
{
  "slot_id": 1,
  "offering_id": 1,
  "session_date": "2026-10-03",
  "scheduled_start": "2026-10-03T10:30:00+05:30",
  "scheduled_end": "2026-10-03T11:30:00+05:30",
  "window_seconds": 300,
  "rotation_seconds": 30,
  "topic": "Introduction"
}
```

The QR response contains `session_id`, `step`, `token`, and `expires_at`. The student-facing manual value is:

```text
A1.<session_id>.<token>
```

## Student submission

```http
POST /attendance/submissions
```

The request includes `session_id`, `android_id`, `qr_token`, `client_nonce`, `signature`, and optional app metadata. The signature is generated by the registered device key.

## Roster and manual edit

```http
GET /attendance/sessions/{session_id}/roster
PATCH /attendance/sessions/{session_id}/records/{student_id}
```

Manual edit example:

```json
{
  "status": "PRESENT",
  "reason": "Verified by faculty"
}
```

Accepted statuses are `PRESENT`, `ABSENT`, and `EXCUSED`. A reason must contain at least five characters.

## Device registration

Admin:

```http
POST /device/registration-window
```

Student/browser:

```http
POST /device/register/challenge
POST /device/register
```

The registration window is one-time and expires after the configured duration.

## OpenAPI

Interactive documentation is available while the backend is running:

```text
http://localhost:8000/docs
http://localhost:8000/openapi.json
```
